# 가사 플레이어 TV (Android TV / 안드로이드 박스용)

기존 `lyric-player_10.html` 을 그대로 쓰는 앱입니다. 화면은 같은 코드이고, 안드로이드 앱이 아래 세 가지를 맡습니다.

1. **USB 직접 접근** – 파일 관리자(AnExplorer 등)나 시스템 파일 선택창 없이 앱이 USB 를 직접 읽습니다.
2. **리모컨 연동** – 방향키·확인·뒤로·메뉴·미디어 키로 모든 메뉴를 조작합니다.
3. **설치 후 바탕화면 표시** – 안드로이드 TV 홈과 일반 안드로이드 박스 앱 목록에 아이콘(배너)이 나타납니다.

> ⚠ 이 프로젝트는 안드로이드 SDK 가 없는 환경에서 작성되어 **APK 로 빌드해 실기기에서 시험해 보지는 못했습니다.**
> 화면(리모컨 조작) 부분은 PC 브라우저에서 시험했지만, 안드로이드 쪽(USB·서버·키 전달)은 코드 검토만 거쳤습니다.
> 처음 빌드/실행할 때 오류가 나면 그 메시지를 알려 주세요.

## 1. APK 만들기

### 방법 A – Android Studio (가장 쉬움)
1. Android Studio (Koala 이상) 설치 → **Open** 으로 이 폴더(`LyricPlayerTV`)를 엽니다.
2. 처음 열면 Gradle 8.7 과 Android SDK 34 를 자동으로 내려받습니다 (인터넷 필요, 몇 분).
3. 메뉴 **Build → Build Bundle(s) / APK(s) → Build APK(s)**
4. 완성 파일: `app/build/outputs/apk/debug/app-debug.apk`

### 방법 B – GitHub 에서 자동 빌드 (PC 에 아무것도 설치하기 싫을 때)
1. 이 폴더를 새 GitHub 저장소에 올립니다.
2. 저장소의 **Actions → Build APK → Run workflow**
3. 끝나면 결과 화면의 **Artifacts → LyricPlayerTV-apk** 에 APK 가 있습니다.

## 2. 박스에 설치
- **adb**: `adb connect <박스IP>:5555` → `adb install -r app-debug.apk`
- **USB 메모리**: APK 를 USB 에 담아 박스에 꽂고, 박스의 파일 관리자로 열어 설치 (설정에서 "알 수 없는 앱 설치" 허용 필요). 설치할 때만 파일 관리자를 쓰고, 이후 앱 사용에는 필요 없습니다.

설치 후 홈 화면(또는 앱 목록)에 **가사 플레이어** 가 나타납니다. 안 보이면 박스를 한 번 재부팅하세요.

## 3. 처음 실행
1. 앱을 열고 **USB에서 음악 불러오기** 에서 확인(OK)을 누릅니다.
2. 저장소 권한 창이 뜨면 **허용**.
3. USB 안의 모든 폴더에서 음악(mp3, flac, m4a, aac, wav, ogg, opus)과 **같은 이름의 .lrc(또는 .txt)** 를 찾아 목록을 만듭니다. 폴더가 다르면 같은 이름이라도 서로 섞이지 않습니다.
4. 곡을 고르거나 **재생 시작** 을 누르면 곡 정보 화면을 약 4.5초 보여 준 뒤 음악이 재생됩니다.
5. (선택) USB 를 꽂을 때 뜨는 창에서 이 앱을 **기본으로 사용** 으로 고르면, 다음부터 꽂기만 해도 앱이 열리고 자동으로 불러옵니다.

### USB 를 읽는 방식 (2단계)
| 단계 | 방식 | 지원 형식 |
|---|---|---|
| 1 | 안드로이드가 마운트한 USB/SD 경로(`/storage/XXXX-XXXX`)를 앱이 직접 읽음 | 박스 커널이 지원하는 형식 전부 (FAT32, exFAT, 보통 NTFS 도) |
| 2 | 1단계가 비었거나 접근이 막혔을 때, USB 호스트 API 로 장치를 직접 열어 읽음 (libaums) | **FAT32 만** |

2단계는 USB 사용 허용창이 한 번 뜨며, 리모컨 확인 키로 허용하면 됩니다.

## 4. 리모컨 조작

**재생 화면**
| 키 | 동작 |
|---|---|
| ◀ / ▶ | 10초 뒤로 / 앞으로 (길게 누르면 30초) |
| ▲ / ▼ | 하단 메뉴 열기 |
| 확인 | 재생 / 일시정지 |
| 뒤로 | 한 번: 안내 표시 → 2.5초 안에 한 번 더: 앱 종료 |
| 미디어 키 | 재생/정지, 다음/이전 곡, 빨리감기/되감기 |

**메뉴·목록**
| 키 | 동작 |
|---|---|
| 방향키 | 항목 이동 |
| 확인 | 선택 |
| 뒤로 | 메뉴 닫기 / 종료 안내 |

볼륨은 TV 리모컨의 시스템 볼륨을 쓰거나 하단 메뉴의 앱 내부 볼륨을 사용하세요.

## TV 화면 구성 및 부하 최소화

- 곡이 바뀌면 **앨범 커버, 곡 제목, 가수명**을 먼저 표시합니다. 곡 제목 양옆에만 굵은 짧은 선을 넣고, 선 길이는 제목 글자 수에 따라 달라집니다. 가수명에는 장식선을 넣지 않습니다.
- 곡 정보 화면을 약 **4.5초** 보여 준 뒤 실제 음악 재생을 시작하고 가사 화면으로 전환합니다. 대기 중에는 음악 시간이 흐르지 않으며 LRC 싱크도 재생 시작 시점부터 맞춥니다.
- MP3(ID3 APIC), FLAC(Picture), M4A/MP4(covr)의 내장 커버를 읽습니다. 커버가 없거나 읽을 수 없는 파일은 간단한 음표 표시를 대신 사용합니다.
- 재생 중에는 기본적으로 검정 배경에 큰 흰색 가사만 표시합니다. 가사는 타임스탬프에 맞춰 즉시 교체됩니다.
- **가사 연출 (v1.9)**: **한 곡에는 효과 1개만** 쓰고, 곡이 바뀔 때마다 켜져 있는 효과 중 하나를 랜덤으로 고릅니다(바로 앞 곡과 같은 효과는 피합니다). 모든 효과는 줄 전체에 걸리는 애니메이션 1개이고, 길이 0.45초 이하, 이동 거리 작게, 반복·튕김 없음입니다. 재생 중 리모컨 **메뉴 버튼**(또는 하단 메뉴의 **가사 연출**)으로 켜고 끌 수 있으며, 메뉴 위쪽에 이 곡에 적용된 효과가 표시됩니다. 설정은 저장됩니다. 특정 효과를 시험하려면 "모두 끄기" 후 그 항목만 켜세요.
  | 효과 | 하는 일 |
  |---|---|
  | 아래에서 살짝 떠오름 | 나타나며 살짝 올라옴 |
  | 위에서 살짝 내려옴 | 나타나며 살짝 내려옴 |
  | 옆에서 짧게 밀려옴 | 아주 짧게 옆에서 들어옴 (방향은 곡마다 고정) |
  | 살짝 커지며 나타남 | 96%에서 100%로 |
  | 밑줄이 가운데서 늘어남 | 줄 아래의 가는 선이 가운데서 양옆으로 |
  | 이전 줄이 서서히 사라지며 겹침 | 나타나는 효과 없이, 이전 줄이 0.24초 동안 사라짐 |
- **배경**: 곡마다 항상 적용되는 정지 그라데이션 3겹(가운데 은은한 빛, 모서리의 약한 다른 색, 위아래 어둡게)입니다. 움직임·블러·합성 효과는 없고, 밝기는 낮게 유지해 흰색 가사가 잘 보입니다. 어두운 그라데이션에서 줄무늬가 보이면 알려 주세요.
  글자별 애니메이션, 블러, 캔버스 배경, 오디오 분석(WebAudio)은 쓰지 않습니다. TV 버전의 오디오 경로(HTMLMediaElement 직접 출력)는 그대로입니다.
- 배경 파문, 비·입자·선 등 모든 모션 그래픽과 그래픽 설정 메뉴를 TV 버전에서 제거했습니다. 화면 해상도/경량 모션 선택지도 제거하고 WebView는 기본 해상도로 표시해 글자를 선명하게 유지합니다.
- USB 검색, 재생목록, 랜덤 재생, 리모컨, 볼륨, 탐색 기능은 유지합니다.

## 6. 알아 둘 점
- **안드로이드 System WebView 가 너무 오래된 박스**에서는 일부 효과가 안 나오거나 느릴 수 있습니다. Play 스토어에서 *Android System WebView* 를 업데이트하세요 (Chrome 100 이상 권장).
- **WMA, ALAC, APE** 등은 WebView 가 재생하지 못해 목록에서 제외합니다. 재생이 안 되는 곡을 만나면 자동으로 다음 곡으로 넘어갑니다 (연속 5회까지).
- 앱 종료는 하단 메뉴의 **✕ 종료** 또는 뒤로 키 두 번입니다. 홈 키로 나가면 음악은 계속 나옵니다.
- 앱 안의 내부 서버는 `127.0.0.1` 에서만 열리고, 실행할 때마다 바뀌는 비밀 주소를 쓰므로 같은 기기의 다른 앱이 USB 파일을 가져갈 수 없습니다. 외부 인터넷은 사용하지 않습니다 (INTERNET 권한은 내부 서버 접속에 필요).
- `targetSdk` 를 29 로 둔 것은 안드로이드 10/11 이상에서도 USB 경로를 직접 읽게 하려는 의도입니다 (Play 스토어 배포용이 아니라 직접 설치용).

## 7. 문제 해결
| 증상 | 확인 |
|---|---|
| "마운트된 USB/SD 저장장치를 찾지 못했습니다" + 2단계도 실패 | USB 를 다른 포트에 꽂아 보기 / 박스 설정에서 USB 가 인식되는지 확인 / exFAT·NTFS 인데 박스가 마운트를 못 하는 경우는 FAT32 로 포맷 |
| "읽기 권한이 없습니다" | 설정 → 앱 → 가사 플레이어 → 권한에서 저장소(또는 음악/오디오) 허용 |
| USB 허용창이 안 뜸 | USB 를 뽑았다 다시 꽂고 앱에서 다시 불러오기 |
| 가사가 안 붙음 | 음악과 가사 파일 이름이 (확장자 제외) 같고 같은 폴더에 있는지 확인 |
| 화면이 안 뜸 | 뒤로 키로 종료 후 재실행. 계속되면 WebView 업데이트 |
| 원격 디버깅 | 디버그 빌드는 PC 크롬의 `chrome://inspect` 에서 박스(adb 연결)의 WebView 를 볼 수 있음 |

## 폴더 구조
```
app/src/main/assets/index.html      ← 가사 플레이어 화면 (lyric-player_10 + TV/리모컨/USB 코드)
app/src/main/java/.../MainActivity  ← 웹뷰, 리모컨 키 전달, USB 검색 호출
app/src/main/java/.../UsbScanner    ← 1단계(마운트 경로) + 2단계(libaums 직접 접근)
app/src/main/java/.../LocalServer   ← 127.0.0.1 서버: 화면 + USB 파일(Range 지원)
app/src/main/java/.../Entry, Library
app/src/main/AndroidManifest.xml    ← 런처/배너, USB 연결 시 실행, 권한
```


## TV 오디오 안정화 빌드 (v1.2)

- Android TV에서는 Web Audio `AnalyserNode` 기반 비트 분석을 끄고 HTML 오디오 기본 출력 경로를 사용합니다. PC 브라우저에서는 기존 비트 분석을 유지합니다.
- TV 가사 동기화 루프는 약 10fps로 제한합니다. (v1.3부터 배경 캔버스 효과는 제거됨)
- TV에서 저사양 모션 설정을 기본 적용합니다.
- 곡 전환 때 기존 오디오를 먼저 정지하고 새 소스를 `load()`하여 이전 디코더/요청과 겹치는 일을 줄입니다.
- WebView 렌더러 우선순위를 중요 작업으로 지정하고 USB 오디오 응답의 소켓/출력 버퍼를 확대했습니다.

참고: HTML 오디오의 내부 디코더 버퍼 크기는 WebView가 관리하므로 앱에서 임의의 초 단위로 직접 지정할 수 없습니다. 이번 변경은 재생 경로와 USB 스트리밍의 병목 가능성을 줄이는 방식입니다.

## TV 정적 가사 빌드 (v1.3)

- 곡 정보 선표시 후 4.5초 뒤 오디오 재생을 시작하도록 변경했습니다.
- 내장 앨범 커버 및 제목/가수 태그를 표시합니다.
- TV에서는 배경 그래픽, 그래픽 설정, 저해상도 렌더링 선택을 사용하지 않습니다.
- TV 가사는 타임스탬프에 맞춰 즉시 교체합니다.
